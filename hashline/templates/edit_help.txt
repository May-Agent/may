edit — apply a per-line hashline patch from standard input

USAGE:
    edit <<'PATCH'
    [src/greet.py]
    PUT 1#PM.=3#VK:
    +def greet(name):
    +    print(f"Hi, {name}")
    PATCH

Every file section starts `[PATH]`. Every line anchor `N#HH` comes from your
latest `search` (`sed` / `cat` / `head` / `tail` / `nl` / `rg` / `sg`) or prior
`edit` output (`N#HH|content`) and names the ORIGINAL lines — applied hunks
never shift the numbers of later ops in the same patch. Every anchor is checked
against live disk contents before any write lands; any mismatch refuses the
whole patch atomically and prints live `N#HH|content` context with moved-line
hints.

OPS — headers ending in `:` take `+` body rows; the rest take none:
    PUT N#HH.=M#KK:    replace original lines N–M (inclusive) with the body
    PUT N#HH:          replace one line (same as PUT N#HH.=N#HH:)
    PUT N#HH*:         replace the syntactic block beginning on line N
    PUT <N#HH:         insert the body before line N  (PUT <1: = file head, works on empty files)
    PUT >N#HH:         insert the body after line N   (PUT >$: = file tail)
    PUT >N#HH*:        insert the body after the block beginning on line N
    CUT N#HH           delete line N (optional `@reg` capture)
    CUT N#HH.=M#KK     delete lines N–M (optional `@reg` capture)
    CUT N#HH*          delete the block at N (optional `@reg` capture)
    YANK R N#HH        copy line N into register R without deleting
    YANK R N#HH.=M#KK  copy lines N–M into register R without deleting
    YANK R N#HH*       copy the block at N into register R without deleting
    PASTE R <N#HH      paste register R before N (also >N#HH, <1, >$, >N#HH*, N#HH, N#HH.=M#KK, N#HH*)
    REM                delete the file (stands alone in its section)
    MV DEST            move the file to DEST; ops above land first

REGISTERS — `YANK R …` copies lines into register `R` without deleting;
`CUT … @R` deletes and captures into `R`; `PASTE R …` (or bodyless `PUT … @R`)
pastes `R` at a gap or over a range/block, including across files in the same
patch.

BODY ROWS — every body row is `+TEXT`, verbatim (leading whitespace kept; never
include the `N#HH|` prefix); `+` alone is a blank line. There are no `-old` or
context rows: the range deletes, the body is only the final content. A literal
leading `-`/`+` keeps its prefix: `+- item` writes `- item`, `++ item` writes
`+ item`.

RULES:
    - Copy `N#HH` directly from `search` or prior `edit` output; ranges cover
      ONLY changed lines.
    - Re-ground from the echoed `N#HH|content` lines after each edit; on a hash
      mismatch, use the printed live anchors or re-run `search`.
    - Never start or end a range mid-expression or mid-block; a whole construct
      is `PUT N#HH*:`, lines inside one are `PUT N#HH.=M#KK:`.
    - Block ops anchor the OPENING line of a multi-line construct — a leading
      decorator/attribute is part of it (point N at the decorator); one
      statement or a closing line is a plain `PUT`/`CUT`, not `N#HH*`.
    - Never format code with this tool; run the project formatter.
    - Create new files with redirection; `edit` edits existing ones.
