edit — apply a hashline patch from standard input

USAGE:
    edit <<'PATCH'
    [src/greet.py#A1B2]
    PUT 1.=3:
    +def greet(name):
    +    print(f"Hi, {name}")
    PATCH

Every file section starts `[PATH#TAG]`; the tag and the line numbers come
from your latest `search`/`cat` output of that file and name the ORIGINAL
lines — applied hunks never shift the numbers of later ops. A tag that no
longer matches the live file refuses the whole patch.

OPS — headers ending in `:` take `+` body rows; the rest take none:
    PUT N.=M:      replace original lines N–M (inclusive) with the body
    PUT N:         replace one line (same as PUT N.=N:)
    PUT N*:        replace the syntactic block beginning on line N
    PUT <N:        insert the body before line N  (PUT <1: = file head)
    PUT >N:        insert the body after line N   (PUT >$: = file tail)
    PUT >N*:       insert the body after the block beginning on line N
    CUT N.=M       delete lines N–M and capture them
    CUT N*         delete the block at N and capture it
    REM            delete the file (stands alone in its section)
    MV DEST        move the file to DEST; ops above land first

REGISTERS — a `CUT … @name` captures into a named register; a bodyless
`PUT` pastes it (`PUT <9 @name`, `PUT >9 @name`, `PUT >$ @name` at a gap,
`PUT 4.=7 @name` over a range, `PUT 4* @name` over a block). An unlabeled
`CUT` + unlabeled gap `PUT` moves once within one patch. Named registers
move content between files' sections in the same patch.

BODY ROWS — every body row is `+TEXT`, verbatim (leading whitespace kept);
`+` alone is a blank line. There are no `-old` or context rows: the range
deletes, the body is only the final content. A literal leading `-`/`+`
keeps its prefix: `+- item` writes `- item`, `++ item` writes `+ item`.

RULES:
    - Touch only lines you have seen: numbers come from output that carried
      this file's current tag, and ranges cover ONLY changed lines.
    - Re-ground after every edit: the response echoes the file's new tag
      and the changed lines; stale tag? STOP, run `search` or `cat` again.
    - Never start or end a range mid-expression or mid-block; a whole
      construct is `PUT N*:`, lines inside one are `PUT N.=M:`.
    - Block ops anchor the OPENING line of a multi-line construct — a
      leading decorator/attribute is part of it (point N at the decorator);
      one statement or a closing line is a plain `PUT`/`CUT`, not `N*`.
    - Never format code with this tool; run the project formatter.
    - Create new files with `write`/redirection; `edit` edits existing ones.
