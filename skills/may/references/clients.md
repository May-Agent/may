# Clients

Every client is a front end of the one daemon; a turn started in one is visible in all, and closing a client — a web UI window, or a TUI that crashes or loses its terminal — does not stop it.

When the daemon itself exits unexpectedly (a crash or a kill, not `may daemon stop` or a rebuild's replacement), its next start ends every process the exited daemon left running and tells each interrupted session — one with a turn in flight or background commands or subagent runs alive — that the daemon exited and all its background commands are gone. A session whose prompt cache is still warm starts again at once with that alert; one whose cache went cold waits, and the alert arrives with the user's next message. A turn's input is stored when the turn starts but the agent's context is checkpointed later, so the agent rebuilt after the exit also gets the user messages and hidden context stored after its last checkpoint, and sees what the cut-off turn was answering.

## Command line (`may`)

- `may`: the TUI in the current directory. `may chat`: the TUI with repo-less chats (no directory, no repository, like the web UI's New chat). `may --repo <owner/repo or path>` starts a session directly on a repository; `owner/repo` needs no local checkout, and the repository's trust question is asked when the session starts. `may resume [session-id]` reopens a session (the most recent without an id).
- The TUI session picker groups regular sessions by project (GitHub projects by `owner/repo`, local ones by path; repo-less sessions first); `N` starts a new chat under the highlighted session's project.
- A session in a checkout of a GitHub repository whose trust is decided is checked at its first turn: a clean checkout holding the remote's latest work proceeds silently; a dirty, behind or diverged one asks whether to base on the latest clean remote (the session is bound to `owner/repo`), base on this checkout (uncommitted and untracked files become a base commit the work stacks on; a checkout that is current keeps the GitHub binding with the base commit on a clone of the remote, while a checkout that is both stale and dirty is bound to the checkout and uses May's own issues and PRs), or exit. When the remote cannot be reached the question is whether to continue on the checkout as it stands (bound to the checkout, its uncommitted files carried) or exit. Choosing exit ends the turn without an error: the web UI shows a plain notice and the TUI a status line. `repo trust set` binds the session to the repository at once, replacing an earlier binding. Starting the TUI's next session on a repository also works from inside it with `/new <owner/repo or path>`. A git author (`user.name`, `user.email`) is required to carry a checkout's work in progress; without one the start fails and names the settings.
- `may "<prompt>"`, optionally `--model <id>` and `--reasoning-effort <low|medium|high>`: one-shot run; assistant text goes to stdout, process events to stderr. Permission prompts are refused rather than asked. One-shot runs and the TUI use the Build profile.
- `may ui`: starts the daemon if needed and opens the web UI (only in a build with the `ui` feature). `may rest [--host <addr>] [--port <port>]` runs the daemon in the foreground, API only.
- `may daemon [install|uninstall|status|stop]`: run, install as a login service (launchd or systemd), report or stop the daemon.
- `may browser <status|open|close|targets|contexts|cdp-endpoint|read <url> [--detail brief|standard|full] [--screenshot off|viewport|full-page]|provision|kill>` inspects the managed browser; `may exec --session <id> [...] <command>` runs a command in a session's home environment.

## TUI

Typing sends: Enter sends the line. While the agent is working, Enter steers (interrupts the turn with the new message) and Tab queues the message to run after the turn. Tab also accepts a shown prompt suggestion. A turn stopped before any output puts the sent text back in the input.

- Layout: the chat and the input share a two-column side margin. The input has no `>` prompt and starts flush left; a leading `!` gets the bash-mode highlight instead. The input, the status line (`cwd · model · tok/s · index`, context size on the right) and each user message in the chat sit on the same full-width band shade (read from the terminal at startup; the terminal's default background when it does not answer), with one padding row above and below the band, one blank row between input and status, and one plain row between the chat and the band. Queued-message lines stay above the band.
- `/` opens the slash palette (see `slash-commands.md`); `@` opens file-mention completion, inserting the path of a file from the working directory or sandbox.
- `! command` runs a bash command in May's environment; its masked output is returned to the agent as the next message. Never type secrets there; use `/secret`.
- Ctrl+V pastes (an image becomes an attachment); a multi-line or large paste becomes an attachment file.
- Ctrl+B shows or hides the sidebar (tasks, issues, subagents, jobs; only on terminals at least 120 columns wide). Issue rows carry GitHub-style state icons: a green ● for open, a dark ✓ for closed. PR rows show the live check rollup from GitHub: a green ● while the read is pending, yellow ● with checks running, red ● on a failure, and a green ✓ once all required checks pass (green ● while the PR sits in the merge queue); the collapsed row carries the finished-of-total figure (`3/5`), and a click (or expanding everything) opens the PR into its checks, each with its state (✓ passed, ✗ failed, ● running, ○ queued) and its elapsed or total time, a failed one followed by its GitHub link. A check read that failed is stated on the expanded row. The web UI's Details tab lists the same in-flight PRs under "Pull requests", pushed as `prs.changed` on the session event stream. Ctrl+N new session, Ctrl+P profile or session list, Ctrl+Left open questions, Ctrl+C clear / twice quit, Ctrl+Q quit. Up/Down browse input history or scroll the chat, PageUp/PageDown and the mouse wheel scroll, g/G jump to top/bottom, Esc clears the input, Esc twice (idle) opens rewind. Selected text is copied with Ctrl+C.
- A warning for the user, such as an abnormally long CI job, appears in the stream with a warning icon in yellow; it is not part of the agent's context. The web UI shows it with an amber warning icon.
- The sidebar keeps the session title fixed and scrolls everything under it: the mouse wheel over the sidebar (while its content overflows; otherwise the wheel scrolls the chat) or Alt+Up/Alt+Down, with a dim `↑ N  ↓ M` row at the bottom counting the rows off screen. Clicking a section heading (▾ open, ▸ folded) folds or unfolds it; clicking a `… N more` row lists every entry of that section (`show fewer` folds it back); clicking a task row marked ▸ shows its detail lines. Alt+E opens every section, list and detail at once. This state is per session and lives in the client.
- A chat opens with a welcome header as the stream's first element, so it scrolls away with the conversation: a block-character black cat with yellow eyes (in the terminal's foreground colour), then `May`, the version and the working directory (home written `~`) beside it. Terminals too narrow for the logo and a readable path show the text alone; a path that still does not fit loses its head behind `…`. It has no border or divider.
- The TUI draws surfaces as filled colour blocks, never as lines: the input band, user messages (one shaded padding row above and below), the sidebar (a background-coloured block, no divider), and every popup, panel and completion list (a title row inside the block, selection shown by the row's background). The block colour is derived from the terminal's own colours.
- Dialogs appear for approvals: `unsafe` command permission, workspace access outside the sandbox, repository trust, `ask_user` questions, and a quit confirmation when the session's agent is working — a run active, or background commands or subagent runs alive: keep it running in the background, or stop it (the run and its background work) and quit. An open question lists the `tasks.md` rows marked `BLOCKING <its request id>` (the TUI sheet shows three and a count of the rest; the web UI's question card lists them all), following the document as it changes. Tool calls can be opened for detail and images viewed full screen.
- A `terminal` call is read before it runs. A command May understands from its literal words (`apply_patch`, `cat`/`head`/`tail`/`sed -n`/`nl`, `rg`/`grep`/`fd`/`find`, `ls`/`tree`, `git`, `cargo`/`bun`/`npm`/`uv`/`make`) shows as a step in plain words, and an `apply_patch` shows as a diff per file with the file's absolute line numbers: the patch is parsed and its hunks placed in the file as `apply_patch` itself will place them, and a hunk that does not place is shown without numbers. The same reading fills the approval dialog. A command it does not understand (variables, substitutions, globs where a path is expected, unknown programs, a malformed patch) shows as the raw command, as before; so does a script with no understood command. A reloaded session shows an edit's diff without line numbers for updated files.
- Markdown images in assistant replies and image artifacts (`<artifact url="…png"/>`) render inline on terminals with image support (Kitty, iTerm2, Sixel); while an image is fetched or after a failed fetch its reserved rows show a `▏image · caption` placeholder. On terminals without image support they degrade to a link.

## Web UI

Served by the daemon at `http://127.0.0.1:8787` (or the remote address, see `remote-access.md`) when built with the `ui` feature. Routes: `/p/<profile>` (profile home), `/p/<profile>/s/<session>` (a chat), `/p/<profile>/archive`, `/settings`. A 401 from the daemon shows a sign-in-required page.

- Sidebar: profile switcher and New profile; New chat (and New chat in a GitHub repo, with a searchable repository list that needs `gh auth login`); sessions grouped Pinned (with folders), Recent and Archived; Recent sessions bound to a repository group under a project header (GitHub logo and `owner/repo`, never a path, for a GitHub project; the checkout's path for a local one) with a button for a new chat under that project, while repo-less sessions stay ungrouped above; per-session actions Pin/Unpin, Move to folder, Archive/Unarchive, Rename, Delete; notifications bell; Settings.
- Shortcuts: Cmd/Ctrl+N new chat (Cmd/Ctrl+Shift+O also), Cmd/Ctrl+K command palette (sessions, new chat, settings, theme, language), Ctrl+Cmd+S (Mac) or Ctrl+Alt+S show/hide sidebar, Option+Cmd+0 (Mac) or Ctrl+Alt+0 show/hide inspector.
- Composer: Enter sends, Shift+Enter newline, attach files, `!command` bash mode, a Queue toggle (queue until the turn ends instead of interrupting), a model picker, a thinking-effort picker, and a stop button. Only `/sleep` and `/sleep off` are slash commands here.
- Chat: streaming reply with decode speed (`show_decode_speed`), collapsible reasoning ("Thought for ..."), tool cards (a `terminal` card and its permission modal show the call's reading, with diffs for `apply_patch`, as in the TUI; an unreadable command stays the raw command), copy buttons, translation of replies into the interface language with a show-original toggle, a context ring (percent of the window used), banners when held on a quota limit, provider retry or network wait, and a plan banner (plan off / draft / approved, with Approve, Discard and Edit of `tasks.md`). The task sidebar (TUI and web) shows each `tasks.md` row's title only. A yolo switch sits above the composer. Permission, workspace and `ask_user` requests open as modals (secret questions take a value that May never sees).
- Inspector (side pane): Details (rename, tasks with progress, linked issues, subagents with stop, background jobs with stop), Library (files May made, also the Files drawer), Browser and Computer (live view of the agent's managed browser or session desktop; Take over pauses May until you hand back).
- Settings: see `configuration.md`. Interface languages: English (US), Traditional Chinese, Japanese, picked from the browser's language on first load. Themes Light, Dark, System.
