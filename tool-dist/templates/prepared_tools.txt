{% if hashline %}### Hashline `search` and `edit`
- Read files with `search sed`/`search rg`/`search cat`/`search head`/`search tail`/`search nl`/`search sg` (`--lang <lang>`) for `[PATH]` headers and `N#HH|content` anchors; bare `rg`/`sed -n`/`cat`/`head`/`tail`/`nl` are auto-rewritten to `search …` unless `raw: true`.
- Edit existing files only via `edit <<'PATCH'` (never `sed -i`, scripts, redirects, `tee`, or `cp`/`mv`); create new files via redirection.
- Sections start `[PATH]`; copy each line's `N#HH` anchor from `search` or prior `edit` (mismatched hashes reject the whole patch with live lines).
- Ops (`:` headers take `+TEXT` verbatim, no `N#HH|` prefix; `+` = blank line; no `-old` rows):
  - `PUT N#HH:` / `PUT N#HH.=M#KK:` / `PUT N#HH*:` replace line / range / block
  - `PUT <N#HH:` / `PUT >N#HH:` / `PUT <1:` / `PUT >$:` insert before N / after N / BOF / EOF
  - `CUT N#HH.=M#KK` / `CUT N#HH*` delete; `REM` remove file; `MV DEST` move file
```sh
edit <<'PATCH'
[src/main.rs]
PUT 3#PM.=5#YN:
+    new_call();
PATCH
```
- Run `search --help` / `edit --help` for `YANK`/`PASTE` registers and advanced options.
